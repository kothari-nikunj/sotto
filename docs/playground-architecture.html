Numbered task selection

The cleanup tool binds explicit all, all-except and numeric selections to the exact accepted displayed open list, including an exact requested subset. Numeric answers to its done question can omit the completion verb; bare numeric questions stay unchanged. An All? prefix needs every displayed index and a complete snapshot. The journal's owner-task-selection helper preserves a validated list for one typed repair only when clarification acceptance was frozen before the next owner event. Ordinary prose cannot supply selection authority. Numbered spans live in owner-task-scalars; the receiver writer uses the pure cleanup_selection predicates and independently revalidates current targets. No helper owns a new store. Unseen, excluded, explicitly open and unmentioned rows stay untouched. Source, identity, route, delivery and row-version checks remain; partial or uncertain effects retain their recovery.

Everything that crosses the two processes

The Node chat runtime and trigger receiver share the tenant $SOTTO_DATA volume through disjoint state directories. The receiver owns canonical memory and delivery; the chat engine is replaceable. Canonical sidecars use their designated writers and atomic replacement; concurrent mutations use the shared sidecar lock. The receiver's work queue and outbox separately own durable admission and delivery. Skills run from the immutable image, never from the volume. Node keeps its private state under node-state/ and leaves the receiver as the canonical writer.
