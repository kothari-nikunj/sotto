Everything that crosses the two processes

Hermes and the trigger receiver share exactly one thing: the $SOTTO_DATA volume. Every JSON write goes through connectors.write_json (tmp at 0600 → os.replace), so a crash mid-write can never leave a torn file. Every row but the last is one-way — exactly one writer, readers that never write. That is the property that lets two processes share a volume with no lock.

Account and device are separate

The Cloud account service registers isolated tenant routes and binds verified Google issuer/subject identities. Email admits an account once; it cannot transfer an existing tenant. Browser Google connection needs no Mac key. A device-authenticated status endpoint reports the existing source, messaging and first-delivery facts. The shared source catalog excludes Contacts-only access from personal brief readiness. Later Bridge enrollment signs its own device grant against the same account. Shared-number routing remains a separate release gate.

Mac source onboarding

Cloud and self-host share the source list and Full Disk Access card. All Mac sources start on for new installs, with visible toggles before the first read. Google sign-in alone does not start collection. Startup and reconnect wait for source confirmation; explicit skip disables every Mac reader. Upgrades keep saved choices. Enabled, accessible and successfully read are separate states. Google handoff generations are durable before credential installation, so a crash cannot allow an older reconnect to restore superseded permissions.
