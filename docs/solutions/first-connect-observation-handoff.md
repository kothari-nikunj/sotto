# Let current work guide the history discovery

- Symptom: the discovery composer received only the highest-ranked person's historical fact.
- Cause: onboarding discarded other eligible observations before current tasks and replies were available.
- Fix: hand off up to six observations, taking one per person before additional facts.
- Evidence: every observation keeps canonical identity, observation date and source references.
- Boundary: current asks and later replies decide whether an action is useful; history alone creates no debt.
- Delivery: the existing consent rechecks, discovery claim and interruption budget remain unchanged.
- Proof: disposable protected-ledger and review-context tests; bounded actual-model acceptance is recorded separately.

The history-discovery envelope carries the evidence once. The runner writes an empty person-knowledge
map in its disposable composition inputs for this path, because a name-keyed map loses provenance and
collapses different people with the same name. This does not erase or change canonical knowledge.
The composer already receives the current obligation ledger and messages; no retrieval, ranking-model
call, or learning stage is added. Coverage stays at envelope level and each fact names its supporting
sources. Ineligible and conflicting facts remain excluded before the bounded selection.

The six-observation cap is a context bound, not a claim that every learned relationship was compared.
Existing importance order is retained within the round-robin selection; usefulness is judged by the
existing composer against current evidence. A model-free handoff test does not establish that the
model selected the best opportunity or that a welcome arrived on a device.

Actual-model acceptance exposed a second handoff loss: the critic manifest omitted the history
discovery purpose, observations and coverage. A manifest-only revision could therefore replace the
discovery with an ordinary attention recap. The manifest now carries the same bounded handoff
instruction and evidence used by initial composition. This adds no model call or action authority.

The next trace isolated a second cause: the static extraction system required ordinary daily brief
sections and declared only its own instructions authoritative, while discovery purpose lived in
the user data turn. The existing fixed discovery direction now also serves as the extraction system
suffix and the critic/revision policy prefix. Observation text, identities and coverage remain in
data, never the system instruction. The normal brief system stays unchanged; the discovery suffix
is fixed across discovery runs.

For same-name people, the fixed discovery policy requests names and relevant roles in visible prose;
canonical IDs belong only in existing hidden markers. Actual-model acceptance fixtures must use
valid `c_` IDs, person `identifiers` and ledger `contact_identifier`. A synthetic `contact_email`
field does not establish recipient identity and can correctly trigger a conservative mismatch.

Discovery excludes muted display names and known sender identifiers before ranking or selecting
the bounded observations. It uses the existing communication mute predicate, including exact
case-insensitive names and sender/domain rules. Muted history therefore never enters the composer
handoff or consumes an observation slot. A disposable regression proves a muted high-ranked person
is excluded and an all-muted pool produces no discovery.

This exclusion applies when composing a fresh discovery. It does not add a delivery-time mute
recheck to an artifact saved before the preference changed.

## Actionability comes before queue order

A live recommendation picked an acknowledgment of a promise to consult the team, then correctly
identified consultation as the next action when challenged. The existing triage inventory orders
important/unread email; that is not proof a reply is owed. Skill and runtime guidance now require
judging the current exchange before recommending a reply, using the existing full-thread reader
when needed. They keep blocked promises open and allow acknowledgments that contain new asks.
No queue schema, classifier, model stage or task writer changed. Synthetic contrast cases also
passed before this clarification, so they establish covered examples, not measured reliability
improvement or proof that this live failure cannot recur.
